# バックエンドの構成

共通処理は外部サービスや運用設定に直接依存させず、ストレージなどを引数で受け取ります。公開版だけで共通処理のテストは完結しますが、実サービスのデータ収集や分析は再現できません。

| ディレクトリ | 役割 |
| --- | --- |
| `app/application` | 登録、ログイン、プロフィール変更、セッション失効 |
| `app/contracts` | 会員ストア、価格データ、収集・分析処理の接続仕様 |
| `app/domain` | データ型と共通計算 |
| `app/persistence` | SQLite のトランザクションと会員ストアの検証用実装 |
| `app/security` | パスワードハッシュ、トークン処理、レート制限 |
| `app/infrastructure` | 有効期限付きキャッシュと再試行処理 |

## 会員と保存処理

`MemberService` は `MemberStore` と `RateLimiter` を受け取ります。秘密情報や接続先をサービス内に埋め込まず、運用側で実装を組み合わせます。`MemberSettings` は設定ファイルの型・範囲・未知の項目を検査します。公開している設定値は検証用の例です。

セッションと CSRF トークンはランダムに生成し、保存するのはハッシュだけです。プロフィールとパスワードの変更には現在のパスワードと、そのセッションに対応した CSRF トークンが必要です。メール変更時は他のセッションを、パスワード変更時は全セッションを失効させます。変更と失効は同じトランザクションで確定します。

SQLite アダプターは一つの接続をロックで保護し、書き込みには `BEGIN IMMEDIATE` を使います。リビジョンが古い更新は拒否します。別のストアを接続する場合も、更新の競合検査とセッション失効を同じトランザクションに含める必要があります。

この会員サービスは HTTP 層を含みません。運用側で HTTPS、Secure / HttpOnly / SameSite Cookie、Origin 検査、信頼できる接続元の取得、リクエストサイズ制限を実装する必要があります。メール所有確認、メール送信、パスワード再設定、管理者権限もこの共通モジュールの対象外です。

## キャッシュと再試行

キャッシュは件数上限、期限、LRU による削除を持ちます。値はコピーせず保持するため、呼び出し元で変更しない値を渡します。キャッシュと同梱のレート制限は単一プロセス用です。複数ワーカー間では共有されないため、分散ストアが必要です。

再試行処理は、呼び出し元が指定した例外だけを対象に、回数と待ち時間を制限します。同じ処理を繰り返しても重複更新を起こさない操作に使う前提です。キュー、永続化、実行中の処理を止めるタイムアウトは含みません。実行時間の制限は接続先クライアント側でも設定します。

## 公開範囲

店舗固有の接続方法、照合データ、分析の振り分け、プロンプト、本番のデータ構造・認証情報は別管理です。公開側には接続仕様だけを置き、共通コードのテストでは作成したサンプルを使います。

`public/backend-files.json` に公開対象をファイル単位で記載しています。書き出し処理はリスト内のファイルだけを新しい出力先へコピーし、既存の出力先を上書きしません。公開ツリーでは未分類のバックエンドファイル、シンボリックリンク、未公開モジュールへの依存を検査します。秘密情報の簡易検出もありますが、内容確認を代替するものではありません。CI は公開ファイルだけで実行し、運用用の設定やデータを渡しません。

非公開部分の実装は著作権および事業上の理由により掲載していません。公開コードの利用条件はルートの `LICENSE` を参照してください。

公開チェックも Python 3.11 を対象とします。依存検査は通常の静的 import が対象で、任意の動的 import や実行時に組み立てられる依存関係までは保証しません。そうした読み込みを追加する場合は別途確認が必要です。
