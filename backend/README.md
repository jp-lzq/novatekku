# Backend

バックエンドのうち、公開できる共通部分をまとめたものです。

会員管理の共通処理、ストレージとの境界、チャート計算、キャッシュと再試行処理を置いています。`main.py` は引き続き死活確認だけの構成で、会員用の HTTP API は公開していません。

会員サービスには、登録、ユーザー名またはメールアドレスでのログイン、プロフィール変更、パスワード変更、セッション失効を含みます。設定の形式と例は公開し、実際の運用値は外から渡す構成です。SQLite アダプターは共通処理の検証用で、本番のテーブル構造を再現したものではありません。

価格基準の更新では、商品と容量ごとの価格を一度スナップショットにまとめ、金額、取得時刻、必要な商品の不足を確認してから保存側へ渡します。途中までしか取得できなかった場合は、現在の基準値を残す設計です。

店舗との接続実装、商品照合ルール、分析先の選択、プロンプト、本番の保存先やデータは含めていません。これらの詳細を設定例やテストデータに置き換えて公開することもしていません。

検証対象は Python 3.11 です。会員処理、トランザクションのロールバック、競合更新、キャッシュの期限切れ、再試行の上限、公開ファイルの境界を CI で確認しています。構成と制約は [設計メモ](../docs/backend-architecture.md) にまとめています。
